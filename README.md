# Стратегия

Веб-приложение для исследования параметрических матричных игр двух лиц с нулевой суммой. Рабочее пространство организовано вокруг сохранённых моделей: **Модели → Условия → Результат**. Работает на GitHub Pages: вычисления выполняются в браузере, сервер не нужен.

## Запуск на компьютере

Установите Node.js 22 или новее. В папке проекта выполните:

```powershell
npm ci
npm run dev
```

Откройте адрес, который напечатает Vite, обычно `http://127.0.0.1:5173/`.

## Размещение на GitHub Pages

1. Создайте репозиторий на GitHub и загрузите в него содержимое этой папки. Папку `node_modules` загружать не нужно.
2. Основная ветка должна называться `main` или `master`.
3. В репозитории откройте **Settings → Pages → Build and deployment → Source** и выберите **GitHub Actions**.
4. Вкладка **Actions** покажет выполнение workflow **Deploy to GitHub Pages**. Если загрузка файлов была до настройки Pages, запустите workflow кнопкой **Run workflow**.
5. После завершения адрес сайта появится в **Settings → Pages** и в окружении **github-pages**.

Workflow `.github/workflows/deploy.yml` устанавливает зависимости, запускает тесты, собирает приложение и публикует папку `dist`. Настройка `base: './'` позволяет разместить приложение и в корне домена, и в подпапке репозитория. Маршруты не требуют серверных перенаправлений.

Другой статический хостинг также подходит: выполните `npm run build` и опубликуйте содержимое `dist`. Для локальной проверки сборки используйте `npm run preview`.

## Возможности

- Библиотека моделей с поиском, состояниями расчёта, копированием и удалением. Каждая модель содержит название, участников, действия, показатель выигрыша, параметр и единицы измерения.
- Редактор выбранной ячейки: постоянное число, линейная зависимость с отдельными коэффициентами или многочлен. Числовой просмотр матрицы на выбранной точке диапазона помогает проверить оценки.
- Матрица от 1 × 1 до 8 × 8, включая прямоугольные матрицы.
- Безопасный ввод многочленов: `2 + 0.1*t`, `3 - t^2`, `2(t+1)`, `(t+1)^3 / 4`. Поддерживаются `^` и `**`, десятичные точка и запятая. Степень элементов — до 12; исполняемый код не принимается.
- Автоматическое определение степени `w` и исходной степени аппроксимации `u = w × (max(n,m) − 1)`.
- Произвольный диапазон `t` и положительный шаг, от 2 до 501 расчётной точки. Если шаг не делит диапазон нацело, последняя точка — наибольшая точка сетки, не превышающая конец диапазона.
- Исходный пример, квадратичный пример и постоянная матрица.
- На первом экране результата — распределение действий обеих сторон и гарантированный средний выигрыш в рамках модели. Ползунок и список выбирают именно расчётные точки.
- Подробности результата: динамика, таблица дискретных решений, формулы и точность приближения.
- Формулы, коэффициенты, ошибки `Rx`, `Ry`, `Rv` и итоговый критерий `S`.
- Экспорт таблицы в CSV и всей модели вместе с расчётом в JSON. Импорт поддерживает также настройки и расчёты предыдущей версии.
- Попарное сравнение актуальных моделей при общем значении параметра. Проверяются названия показателя, параметра, сторон и их единицы; действия сопоставляются по названиям. При несовместимых условиях приложение объясняет, что нужно исправить.
- Автоматическое сохранение моделей в браузере. Старые настройки и сохранённые исследования переносятся при первом открытии новой версии; прежние записи хранилища остаются на месте.
- Отмена расчёта, сообщения о некорректном вводе, адаптивный интерфейс, справка о методе.

Новое рабочее пространство содержит базовую модель с **настоящим сохранённым расчётом** исходного примера при `w=1`, `u=2`. Такой расчёт явно подписан. Для проверки другого предположения создайте копию, измените условия и пересчитайте её. Результат привязан к условиям, на которых он получен: после численного изменения матрицы, диапазона или весов прежний результат отмечается как устаревший. Редактирование названий не требует повторного вычисления.

Вероятности в результате описывают смешанную стратегию. Выбор только самого частого действия не сохраняет гарантию модели. Приложение не оценивает достоверность введённых пользователем выигрышей и не превращает произвольную бизнес-задачу в игру с нулевой суммой.

## Вычислительный метод

Python-код находится в `src/engine/model.py`. Веб-интерфейс передаёт ему только числовые коэффициенты, диапазон и веса. Pyodide 0.28.3 исполняет Python, NumPy и SciPy в отдельном Web Worker, поэтому расчёт не блокирует интерфейс.

Алгоритм из `Igrovaya_model_matematika.ipynb` сохранён:

1. Сдвиг матрицы `h = 2*abs(min(A))`, если минимальный элемент отрицательный; иначе `h=0`.
2. Две двойственные задачи `scipy.optimize.linprog(..., method='highs')`, нормировка полученных стратегий и возврат исходной цены игры после сдвига.
3. Независимая дробно-рациональная аппроксимация каждой компоненты через `least_squares(method='trf', max_nfev=5000)`, исходная регуляризация `1e-5` и защиты знаменателя.
4. Нормировка приближённых стратегий по сумме компонент.

Добавлено фиксированное зерно `np.random.seed(42)` перед исходным случайным возмущением начальных коэффициентов. Это делает запуск повторяемым; математическая модель и целевые функции не изменены. Циклы обобщены с трёх действий на выбранные размеры матрицы. Итоговый критерий `S = αRx + βRy + γRv` вычисляется дополнительно для вывода.

Положительные веса масштабируют отдельные целевые функции. Исходный метод не содержит совместного подбора всех функций с конкурирующими ошибками, поэтому изменение положительных весов обычно не меняет минимум. При нулевом весе соответствующий подбор не имеет содержательного критерия. Интерфейс сохраняет это поведение и объясняет его.

Сохранены ограничения исходного подхода: приближение не гарантирует неотрицательность вероятностей, отсутствие полюсов и качество между точками. О выявленных нарушениях сообщается. Нулевая вспомогательная цена игры может привести к ошибке исходной формулировки ЛП; программа сообщает её, не подменяя метод.

## Интернет и данные

При первом запуске расчёта браузер загружает Pyodide, NumPy и SciPy с `cdn.jsdelivr.net`. Это занимает время и требует доступа к интернету; последующие запуски используют уже загруженный модуль. Шрифт загружается с Google Fonts; при его недоступности используется системный шрифт.

Матрица, стратегии и настройки не отправляются на сервер. Приложение не использует аккаунты, аналитику или ключи API. Удаление данных сайта в браузере удалит локальные модели. Для переноса и резервного хранения используйте экспорт JSON. Если хранилище браузера заполнено или недоступно, приложение покажет сообщение и предложит выгрузить модели.

## Проверки

```powershell
npm test
npm run build
```

`npm test` проверяет парсер многочленов, приоритет операций, отклонение некорректного ввода, состояния моделей, независимость копий, сохранение и перенос данных, совместимость сравнения и сопоставление действий.

Математические тесты требуют Python с NumPy и SciPy:

```powershell
python -m pip install numpy scipy
python -m unittest discover -s tests -p test_model.py -v
```

Они проверяют исходный пример по аналитическому равновесию, инвариантность стратегий при сдвиге выигрышей, определения невязок и нормировку, прямоугольную квадратичную матрицу и поведение нулевой матрицы. Исходные `.ipynb` и `.docx` сохранены.

Справочные материалы: [размещение Vite на GitHub Pages](https://vite.dev/guide/static-deploy.html#github-pages), [загрузка Pyodide 0.28.3](https://pyodide.org/en/0.28.3/usage/downloading-and-deploying.html).
